# Domain docs

This is a single-context repository.

## Before exploring

Read these when they exist:

- `CONTEXT.md` for domain vocabulary and boundaries.
- Relevant ADRs under `docs/adr/`.

If they do not exist, proceed silently. Domain-modeling work creates them when terminology or architectural decisions are resolved.

## Layout

- `CONTEXT.md`: repository-wide domain context and glossary.
- `docs/adr/`: repository-wide architectural decisions.

Use terms defined in `CONTEXT.md` consistently. If required terminology is absent, record that as a domain-modeling gap.

If proposed work contradicts an ADR, identify the conflict explicitly instead of silently overriding the decision.
